## Повторная настройка или перенос на другой сервер

Эти шаги уже выполнены для текущего проекта. Повторять регистрацию или создавать новый ключ для обычного использования сайта не нужно.

1. Открыть https://console.groq.com/login и войти через Google, GitHub или почту. Вход включает принятие условий Groq; этот шаг выполняет владелец аккаунта.
2. Остаться на **Free**, не переходить на Developer. Бесплатный тариф ограничивает запросы и токены; при превышении сервис отвечает 429. Точные лимиты аккаунта видны в Console → Settings → Limits.
3. В разделе **API Keys** создать ключ, например с названием `posle-sdelki`. Ключ не отправлять в чат и не добавлять в код frontend.
4. Из папки проекта запустить в обычном терминале:

   ```sh
   .venv/bin/python scripts/setup_groq.py
   ```

   Вставить ключ в скрытый запрос. Скрипт сохранит его в исключённом из Git файле `backend/.env` с правами 0600. Существующая настройка базы сохраняется. Скрипт ничего не отправляет в интернет и не меняет тариф.
5. Перезапустить `npm run dev`. В брифе новой тренировки выбрать **AI-собеседник**. Ранее созданные demo-попытки продолжают работать в demo; для проверки нужен новый разговор.
6. Сначала проверить несколько свободных русскоязычных реплик локально. Если подключение и качество подходят, добавить переменные в серверные **Environment Variables** проекта `posle-sdelki` на Vercel и опубликовать проверенный код. Не использовать префикс `VITE_`.

Переменные:

```dotenv
LLM_PROVIDER=groq
GROQ_API_KEY=<ключ из кабинета>
LLM_MODEL=qwen/qwen3.8-27b
LLM_REPLY_MODE=generated
```

`qwen/qwen3.8-27b` на дату проверки указан в бесплатных лимитах и поддерживает строгий JSON Schema. Это **preview-модель для оценки**; доступность может измениться. Реальный запрос в аккаунте команды уже прошёл. Скрипт принимает `--model` для осознанной смены модели; сервер не выбирает другую модель автоматически. Наличие настроек само по себе не доказывает доступ к API.

## Как работает

В `live` с `reply_mode=generated` новая свободная реплика делает два последовательных запроса: анализ намерения и формулировка ответа клиента. При повторе уже сохранённого идентификатора оба запроса пропускаются. Карточки условий, завершение и demo не вызывают AI. Ошибка любого шага оставляет сохранённую попытку без изменений; платного переключения или скрытой подмены демоответом нет.

Для `qwen/qwen3.8-27b` оба запроса используют `response_format: json_schema` с `strict: true`, обязательными полями и `additionalProperties: false`. Это устраняет зависимость от соблюдения моделью просьбы оборачивать обычный текст в JSON. Длина цитаты и ответа дополнительно проверяется локально; параметры длины не передаются в Groq-схему. Используются `reasoning_effort: none` и `reasoning_format: hidden`. Для других моделей Groq адаптер сохраняет JSON Object Mode с локальной проверкой; перед сменой модели нужна отдельная проверка совместимости.

Модель получает учебный контекст и ограниченную историю. Генератору передаются только разрешённые факты, раскрытые интересы и текущий статус предложения; цель из конфигурации, скрытый приоритет, cookie владельца и внутренние события не передаются. Ответ проверяется на формат, новые числовые значения/единицы и очевидное противоречие статусу. Эти проверки не доказывают полной смысловой корректности текста; реальные условия и итог сделки определяет серверный движок.

Настройка `LLM_REPLY_MODE` применяется к новым live-попыткам. Повтор сохраняет режим родительской попытки. Отсутствующее поле `reply_mode` в старой записи означает прежний анализ намерений с ответами по правилам.
