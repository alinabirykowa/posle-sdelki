# Проверка backend v0.2 — 20 сентября 2026

Рабочая копия без коммита. Python 3.12, FastAPI; локальные API 8011 и интерфейс 5174. Проверка не означает готовности публичной среды или конкурсного пакета.

## Изменения

Модель в live возвращает структурированное намерение и точную цитату. Видимые ответы строит сервер из состояния кейса; свободной генерации ответа нет. Предложения и завершение не вызывают модель. Ошибка анализа не сохраняет реплику; повтор сохранённого идентификатора не тратит новый запрос. Деморежим использует ограниченные правила русскоязычных реплик.

Разбор добавляет наблюдения о выяснении потребности, аргументации и ответе на возражение. Каждый пример связан с пользовательским сообщением. Баллы и обучающий эффект не вычисляются. Цитирование, отрицание и неопределённое намерение не засчитываются как собственный вопрос. Сохраняется порядок старых предложений без выдумывания утраченных решений клиента.

Уточнение после предложения показывает его условия и статус. Если пользователь выяснил потребность после отказа, новый ответ учитывает это; прежняя причина отказа остаётся в историческом сообщении, но не повторяется как актуальное требование задать уже заданный вопрос.

## Автоматические проверки

Команда: `.venv/bin/python -m pytest backend/tests -q`.

Результат: **260 passed, 2 warnings in 0.50s**. Полный stdout/stderr сохранён в [backend-v0.2.txt](backend-v0.2.txt). Предупреждения — устаревающие интерфейсы зависимостей TestClient, не ошибки тестов.

- Диалог: перефразировки, посторонние и личные вопросы, собственные и процитированные вопросы, отрицания, контекст, попытки сменить роль.
- Транспорт AI: `httpx.MockTransport`, допустимая схема, точная цитата, лишние поля, пустой/невалидный ответ, таймаут, HTTP 401/429/500, отсутствие секретов в ошибках.
- HTTP → хранение → разбор: откат ошибки, повтор того же ID, неопределённый анализ, защита от неправильно классифицированной моделью цитаты, отказ → вопрос → аргумент → новый пакет, старые попытки, последние согласованные условия.
- Прежние проверки: ресурсные расчёты, правила принятия, сохранение, изоляция браузеров, конкурентный дубль.

`npm run build` успешно выполнил TypeScript и Vite: 1748 модулей, сборка 899 ms. Форматирование исходников выполнено Prettier. После сборки менялись только Python, документация и метаданные версии npm; интерфейсный код не менялся.

## Браузерное прохождение

Codex In-app Browser. Создана одна QA-попытка: `54735e0a-8b94-4865-9e5f-cd293f30ba8e`, scope / deadline / hard / demo. Пользовательские записи не удалялись. В QA-переписке сохранены ответ до исправления старой причины отказа и повторная проверка после исправления.

1. Цитата «В учебнике был вопрос…» вызывает уточнение, не раскрывает ограничение. Платное изменение отклоняется: в сложном режиме собственный вопрос ещё не задан.
2. «Что для вас критично?» раскрывает связь даты запуска с рекламной кампанией.
3. Собственное объяснение замены задач распознаётся как аргумент. После исправления ответ ссылается на уже известное ограничение, а не требует снова его выяснить.
4. Замена задач принята; отдельное подтверждение открывает результат: 120 часов, 15 рабочих дней, остаток после прямых затрат 80 000 ₽.
5. Разбор показывает четыре события в порядке разговора и три наблюдаемых действия. Цитата из учебника не засчитана. Вопрос правильно отмечен как заданный после первого предложения; рекомендация — уточнить потребность раньше.
6. После reload сохранён тот же разбор. На фактической ширине 391 CSS px карточки и цитаты читаемы, горизонтального переполнения нет. После временного расширения измеренная ширина 1422 CSS px равна scrollWidth. Полный визуальный аудит широкого экрана в эту проверку не входит; временный размер сброшен.
7. Журнал браузера на момент завершения не содержал ошибок или предупреждений. Вкладка оставлена на разборе.

## Что остаётся

Нет подключения к реальному AI: совместимость провайдера, качество смысла, задержка и расходы не измерены. Контрольные тесты не являются репрезентативной оценкой точности. Не проверены реальный телефон с клавиатурой, потеря сети в браузере, нагрузка, несколько серверных worker и публичный деплой. Backend пока рассчитан на один процесс. Старые завершённые разборы сохраняются как были и не получают новые поля задним числом.
